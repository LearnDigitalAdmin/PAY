# W3-A — PAY desk patch: notes

Start state: PAY `main` as uploaded (`PAY-main.zip`, no git history; baseline commit `9530166` created from it). Kernel read from CYBER `functions-desk/src` (money.ts, config.ts, types.ts, paystack/splits.ts, commissions/plan.ts).

## What is done
* `functions/src/desk/**`: money (kernel vectors pass), config (`getDeskConfig`, 60 s cache), `resolveDeskOwner`, `getOrCreateDeskSplit` (shared `desk_split_codes` key/shape), `writeDeskEvent` (create-only, same validation as the desk trigger), first-purchase reserve/release, SMS plan + settle, rent tier table + split plan, extracted `initiateRentCharge`, hooks for rent / Plot Yangu subscription / MyChama / refund events.
* SMS: `chargeSmsTopUp` (PMS) resolves `pms:<landlordCode>`, reserves the first purchase in a transaction (30-minute live window), attaches `split_code`, stores `deskCommission` on `sms-topup-transactions/{ref}`. `handlePmsSmsTopUp` and `handleSmsTopUp` write `sms_purchase:<ref>` after the token credit, only when `deskCommission` exists. `charge.failed` and a failed Paystack call release the reservation. Free signup tokens (now `PMS_SIGNUP_FREE_TOKENS = 50`) never earn commission.
* Rent: `processPayment` now delegates to `initiateRentCharge` (take = `rentTake(amount, tier rate, KES 250 cap)`, tier read from `users/{landlord}.tier` at charge time, split via `getOrCreateDeskSplit`, `takeMinor`/shares on `transactions/{ref}`). `setupAccount` uses the same table (`RENT_TAKE_RATE_BY_TIER`). `handleAgentPayment` writes `rent_payment` when the transaction has `deskCommission`.
* MyChama: handlers take an additive `facts` argument (amount, real fee, paid_at) and write the event after the transactional apply OR when already applied (heals a crash between the two); `dispatch.ts` passes `fees`/`paid_at`; the legacy `paystackCallback` passes the same facts. Chama's `deskCommission` may carry only `agentCode`; the id comes from `desk_agents`.
* Plot Yangu subscriptions: `deskCommission` on `subscriptions/{ref}` -> `subscription_payment` (plan, Nairobi `periodMonth`); the legacy 45% block runs only when it is absent (mutually exclusive).
* Refunds: `refund.processed` on both webhooks -> `refund:<refund_reference|id|reference>` only when a non-refund `desk_events` doc has that `paystackRef`.
* `platformCutPct` from `getDeskConfig()` in `chargeCustomer` and `handleCyberCharge`. Samuhia rebrand (`@samuhia.co.ke`, contact emails, FAQ link, manifest, notes).

## NOT done for real (and why)
1. **`desk_runRentBatch` trigger — not shipped.** PMS's repo was not supplied and PAY only shows PMS through its client (`users/{landlord}/tenants/{localId}` with `name`, `users/{landlord}/invoices` with `tenantId` (number), `totalAmount`, `amountPaid`, `arrears`, `isPaid`). Nothing in the supplied code shows the tenant phone field on those records, nor whether desk's opaque `tenantIds` are PMS local ids or `tenants/{uid}`. Guessing would be invented fields. Everything the trigger needs is in place and tested: `initiateRentCharge({ …, desk: { agentId, batchId } })` (owner -> three-way, non-owner -> two-way, resolution failure -> two-way + audit) and the `rent_payment` event. **Needed to finish:** PMS tenant/invoice types and the tenantId convention; then the trigger (transaction `requested -> processing`, ≤200 tenants, 5 at a time, per-tenant dedupe doc) is a small addition.
2. **Register SMS desk commission — resolution not shipped.** The Register repo was not supplied; `chargeSmsTopUp` only receives `schoolId`/`schoolName` from the client and nothing in PAY shows the school document, its KNEC code field, or how a caller belongs to a school. Register top-ups therefore carry no desk part (plain charge, as today). The settle (`handleSmsTopUp`) and failure paths are already wired: once a school top-up stores `deskCommission` on its pending document, the event is written. **Needed:** Register's school document path/fields and membership rule.
3. Real gates not run here: the sandbox has no npm access, so `npm ci`, `tsc --noEmit`, `npm run build`, root `tsc -b && build` could not run. I type-checked with stand-in declarations (no errors in the changed code other than stand-in noise) and ran the tests against stand-in `firebase-admin`/`firebase-functions`/`axios` modules. **Run the gates before merging.** `check:mychama-contract` passes; `test-fees`, `test-migrate`, `mychama-track-a` pass; `test-money-plane`'s callable sections fail identically on the untouched baseline here (stand-in callable runtime), its webhook/signature sections pass.

## Findings and Requests
* `handleSmsTopUp` / `handlePmsSmsTopUp` / `handlePlotYanguSubscriptionCharge` are not idempotent (a replayed `charge.success` credits tokens / resets expiry again). Desk events are safe (create-only) and the desk write never throws, so it adds no retry; fixing the double credit needs a status transaction — Request to the owner of those handlers.
* `processPayment` has no `request.auth` check and trusts client-supplied `agentId`/`amount` (unchanged; the take now uses the amount sent). Request: authenticate and price from the invoice.
* `chargeSmsTopUp` writes the pending document after the charge starts; a webhook arriving first would not find `deskCommission`. Window is milliseconds (STK needs a PIN); moving the write before the charge is a safe follow-up.
* Paystack `refund.processed` payload: relied on `data.transaction_reference` and `data.refund_reference` (from memory of Paystack's docs; could not verify offline). Confirm against the dashboard's sample event.
* `refund.processed` on `mychamaPaystackCallback` required a 3-line edit in `mychama/webhook/index.ts` (a third MyChama file, necessarily).
* `track-C-pay-experience.patch` (historical patch file) still contains the old text; left untouched.
* Deploy with explicit names (`--only functions:<name>`); IAM: none needed.
